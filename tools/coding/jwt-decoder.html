What a JWT Decoder Does
A JSON Web Token (JWT) is a compact, URL-safe token made of three base64url-encoded segments separated by dots: a header, a payload and a signature. The header describes the algorithm, the payload carries the claims (user id, roles, expirations) and the signature protects the token from tampering.
Reading a token by eye is painful because every segment is encoded and compressed onto one line. This tool splits the token apart, decodes the header and payload into readable JSON, and turns the numeric iat, exp and nbf claims into real dates - while also telling you whether the token is currently valid or expired.
How to Decode a JWT in the Browser
  1. Paste the token - copy the full JWT, including all three dot-separated segments, into the text area.
  2. Click Decode token - the tool splits, decodes and pretty-prints the header and payload instantly.
  3. Check the status badge - green means valid, red means expired, yellow means no expiry claim is present.
  4. Inspect the claims table - registered claims like iat, exp and nbf are shown as readable timestamps.
  5. Copy what you need - grab the decoded header or payload with one click, or use the Sample button to see a live token.
Reading Claim Timestamps and Expiry
JWT claims use NumericDate values: seconds since the Unix epoch. iat (issued at) records when the token was created, exp (expiration) records when it must stop being accepted and nbf (not before) records when it may start being accepted. The tool converts each of these to a human-readable date and, if an exp claim exists, compares it with your computer's clock to show whether the token is valid, expired - and if so, how long ago.
Common Use Cases
Backend developers decode tokens returned by OAuth providers while debugging login flows. Frontend engineers inspect what claims they can trust after calling a secured API. QA testers verify that short-lived access tokens behave as configured, and security reviewers check whether tokens carry over-broad claims or suspicious expirations. Whatever the reason, decoding happens entirely inside your tab.
Frequently Asked Questions
Is it safe to decode a JWT here?
Yes. The token is decoded entirely in your browser tab using JavaScript. The token text, its claims and its signature are never uploaded, logged or stored on any server.
Can this tool verify the JWT signature?
No. This tool decodes the header and payload and shows the signature bytes in hex for inspection, but verifying a signature requires the signing secret or public key, which this client-side tool never asks for.
What do the iat, exp and nbf claims mean?
iat is the issued-at timestamp, exp is the expiry (not valid after) timestamp and nbf is the not-before (not valid until) timestamp. The tool converts each into a readable date and shows whether the token is currently valid, expired or missing an exp claim.
Why does my token show as Expired?
A token shows Expired when its exp (expiration) claim is a Unix timestamp in the past relative to your computer's clock. The tool also shows how long ago it expired.
Conclusion
