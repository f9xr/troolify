Bcrypt Hash Generator: Slow by Design, Safe by Default

Bcrypt remains one of the most trusted ways to store passwords because it is deliberately slow and includes a salt. This bcrypt hash generator creates a hash with a configurable cost factor and can verify a password against an existing hash, all inside your browser.

Choosing a cost factor

The cost factor is the base-2 logarithm of the work done per hash. A cost of 10 means 210 iterations; every increment doubles the time for both the defender and the attacker. Pick the highest cost your login system can absorb while staying responsive - 12 is a common modern default.

Salting is automatic

Bcrypt embeds a random salt in the hash string, so two hashes of the same password differ. That defeats rainbow tables and means you never manage salts yourself. The hash already contains the version, cost and salt, which is why verification needs nothing else.

How to use Bcrypt Hash Generator

  1. Enter the password you want to hash.
  2. Set a cost factor appropriate to your hardware.
  3. Click Generate hash and copy the result into your database.
  4. Use Verify to confirm a password against a stored hash.

Tips for getting accurate results

  • Raise the cost as hardware gets faster; store the cost in the hash so old hashes still verify.
  • Never hash on the client in production and send only the hash - do it server-side over TLS.
  • Bcrypt truncates very long inputs, so pre-hash if you allow passphrases beyond 72 bytes.

Key takeaways

  • Bcrypt is intentionally slow and salted.
  • The cost factor trades login latency for resistance to cracking.
  • The hash carries everything needed to verify it.

Frequently asked questions

What cost factor should I use?

As high as your system tolerates. 12 is a reasonable modern default; 10 is a common minimum.

What does the $2b$ prefix mean?

It identifies the bcrypt variant and version. $2a$ and $2b$ behave the same for hashing; the prefix matters mainly for legacy compatibility.

Is bcrypt better than SHA-256 for passwords?

Yes. General-purpose hashes are fast, which helps attackers. Bcrypt is slow and salted specifically for passwords.

Should I hash passwords in the browser?

For real applications, hash on the server. This page is for development, testing and learning.

Is my password sent anywhere?

No. Hashing runs in your browser.
