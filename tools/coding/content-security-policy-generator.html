Content Security Policy Generator: Build CSP Without the Guesswork

A Content Security Policy is the single most effective header for reducing the impact of cross-site scripting. It is also fiddly to write by hand. This Content Security Policy generator lets you set each directive, preview the policy, and export it in the format your server needs.

The directives that matter

default-src is the fallback for everything else. script-src and style-src control code and styles. img-src, font-src and connect-src cover assets and network calls. frame-ancestors replaces the old clickjacking headers, and base-uri plus form-action close common injection tricks.

Start from a preset

The strict preset assumes nothing and locks everything to your own origin. The balanced preset allows 'unsafe-inline' styles, which many apps need, and permits data-URI images. Tune from there rather than starting from an empty policy.

How to use Content Security Policy Generator

  1. Pick a preset or set each directive by hand.
  2. Toggle upgrade-insecure-requests as needed.
  3. Choose the export format for your stack.
  4. Copy the policy into your header, template or server config.

Tips for getting accurate results

  • Deploy in report-only mode first to catch breakage before enforcing.
  • Prefer nonces or hashes over unsafe-inline for scripts.
  • Keep frame-ancestors set to none unless you intentionally allow framing.

Key takeaways

  • A CSP is built up from directives with sensible fallbacks.
  • Presets get you to a safe starting point quickly.
  • Export formats cover headers, meta tags and web servers.

Frequently asked questions

What does a CSP actually prevent?

It limits where scripts, styles and other resources can load from, which neutralises many injection and data-exfiltration attacks.

Should I use report-only first?

Yes. Content-Security-Policy-Report-Only logs violations without blocking, so you can fix issues before enforcing.

Why allow unsafe-inline?

Inline styles or scripts need it, but it weakens the policy. Prefer nonces. This tool leans strict for that reason.

Do meta tag policies work everywhere?

Mostly, but some directives such as frame-ancestors and report-uri are ignored in meta form. Prefer the header.

Is my policy uploaded?

No. Everything is built in your browser.
