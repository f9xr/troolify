Why Strings Need Escaping in JSON

In JSON, every string sits inside double quotes. Because of that, a raw double quote would terminate the string early, a backslash would introduce an accidental escape sequence, and a literal newline or tab would make the document invalid. Escaping replaces each of these with a safe two-character or six-character sequence: \", \\, \n, \t or \u0000-style codes.

The Troolify JSON Escape tool performs this conversion instantly as you type. Whatever you paste - log lines, SQL, user input, shell commands - comes back as a valid string body you can drop between quotes in any JSON document, JavaScript source, or webhook payload.

How to Escape a String

  1. Type or paste your raw string into the input area. Escaping runs live on every keystroke.
  2. Toggle options - escape single quotes, forward slashes, HTML characters, or remove control characters entirely.
  3. Copy the result - the escaped text is one click away, or grab the whole output with the Copy button.

What Each Option Changes

The core escaping always converts double quotes, backslashes, newlines, tabs and other control characters. Escape single quotes also turns ' into \' for environments that favor single-quoted strings. Escape forward slashes turns / into \/. Escape HTML entities converts <, > and & into Unicode escapes, which keeps an inline <script> block from being broken. Remove control chars drops raw control characters below 0x20 instead of converting them.

Use Cases

Developers build JSON payloads from free-text user input, prepare strings for API request bodies, embed generated code in configuration management, and sanitize text before writing it into JavaScript files. Because escaping happens in your browser, even sensitive log snippets never leave the tab.

Frequently Asked Questions

Why do I need to escape a JSON string?

JSON strings are wrapped in double quotes and cannot contain raw double quotes, backslashes or control characters like newlines or tabs. Escaping replaces those characters with backslash sequences (\", \\, \n, \u0009 and so on) so the string can be embedded in valid JSON or a JavaScript source file.

What does the HTML entities option do?

It escapes <, > and & to their \u00XX Unicode forms. This makes the escaped string safe to paste into an HTML script element, preventing the browser from misinterpreting characters like </script>.

What if I want to remove control characters instead of escaping them?

Enable the Remove control chars option. Printable characters stay escaped as needed, while raw control characters below 0x20 are dropped from the output instead of becoming \uXXXX sequences.

Is the escaping performed locally?

Yes. Escaping runs on input, character by character, entirely in your browser tab. Nothing you type is sent anywhere.
