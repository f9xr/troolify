Base64 Encoder & Decoder: Transport Any Data as Safe Text

Whether you are embedding an image as a data URL, passing binary data through a JSON API, or pasting a token into a config file, Base64 is the format that makes arbitrary data behave like plain ASCII text. This encoder and decoder handles both directions instantly, with full Unicode support.

What Is Base64 and Why Do Developers Use It?

Base64 represents binary data using a 64-character alphabet of A-Z, a-z, 0-9, plus and slash. Because the output contains only printable ASCII, it survives email, JSON, HTML attributes, and URL query strings without being mangled.

Common uses include data URLs in <img> tags, SMTP email attachments, storing API keys and tokens, and compacting JSON payloads. Base64 is also the backbone of JWT (JSON Web Token) signatures, where the header and payload are URL-safe Base64 strings.

How to Use the Base64 Tool

  1. Choose a mode - Encode to turn text into Base64, or Decode to turn Base64 back into text.
  2. Paste your input into the box. The result updates live as you type.
  3. Copy the output with one click and drop it into your code, email, or request body.

If the input is not valid Base64 and you are in decode mode, the tool tells you clearly instead of silently returning garbage.

Unicode-Safe Encoding with UTF-8

Plain btoa() breaks on non-Latin characters and emoji because it assumes one byte per character. This tool encodes text to UTF-8 bytes first with the TextEncoder API, then applies Base64, so Wörld, café, 日本語, and emoji all round-trip perfectly. The decoder reverses the same process with TextDecoder.

Pair this with the HTML Entity Encoder when pasting text into web content, or with our UUID Generator when minting fresh identifiers for the data you encode.

Base64 Is Not Encryption

Encoding is reversible by design: anyone with a decoder can read the original content. Never use Base64 to protect passwords, financial data, or personal information. For those you need real encryption, and even then the keys must be handled separately. Treat Base64 as a transport convenience, not a security measure.

Frequently Asked Questions

What is Base64 encoding?

Base64 is a way of representing binary data as ASCII text using a 64-character alphabet (A-Z, a-z, 0-9, + and /). It is widely used to embed data in places that only accept printable text, such as email attachments, data URLs in HTML, and JSON payloads.

Is Base64 encryption?

No. Base64 is an encoding, not encryption. It makes data text-safe and easy to transport, but anyone can reverse it with a decoder, so it must never be used to protect sensitive content.

Does the Troolify Base64 tool handle Unicode and emoji?

Yes. The encoder converts your text to UTF-8 bytes using the TextEncoder API before applying Base64, so accented characters, CJK text and emoji are encoded and decoded correctly without data loss.

Can I decode Base64 from a data URL or JWT?

The decoder accepts a normal Base64 string, so you can paste the payload portion itself. Data URL prefixes such as data:text/plain;base64, and the signature segment of a JWT (which uses URL-safe characters), must be handled separately.
