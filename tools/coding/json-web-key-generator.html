JSON Web Key Generator: Create JWK and JWKS for JWT Signing

A JSON Web Key is the JSON representation of a cryptographic key used to sign and verify JSON Web Tokens. This JWK generator creates RSA, ECDSA and HMAC keys directly in your browser and hands you a public JWK, a private JWK, and a JWKS document you can publish at a /.well-known/jwks.json endpoint.

Because the keys are produced with the Web Crypto API locally, no private material is ever transmitted.

Choosing an algorithm

RSA (RS256, RS384, RS512) uses a public/private pair with PKCS#1 v1.5 padding and is the most widely supported choice. RSA-PSS (PS256, PS384, PS512) is the same key type with the newer probabilistic padding. ECDSA (ES256, ES384, ES512) produces far smaller keys and signatures, ideal for tokens sent over bandwidth-limited channels. HMAC (HS256, HS384, HS512) is a symmetric secret: the same key both signs and verifies, so it must never be shared with a token consumer you do not trust.

Pick RS256 or ES256 when the verifier is a third party; pick HS256 only when signing and verifying happen inside systems you control.

Key ids and rotation

Each key gets a kid. Publishing that id inside the token header lets a verifier select the right key from your JWKS during a rotation, when the old and new keys overlap. This tool derives a random id and reports the RFC 7638 thumbprint so you can cross-check the key you publish.

How to use JSON Web Key Generator

  1. Choose the signing algorithm, RSA modulus size, or EC curve.
  2. Click Generate keys to create the pair locally.
  3. Copy the public JWK (or full JWKS) to publish and keep the private JWK secret.
  4. Paste the private key into your signing service and rotate regularly.

Tips for getting accurate results

  • Never commit a private JWK to source control. Store it in a secret manager.
  • Publish only the public JWKS; verifiers never need the private half.
  • Rotate keys by publishing the new key alongside the old one and using the kid to disambiguate.

Key takeaways

  • A JWKS is simply an array of public JWKs with matching key ids.
  • Asymmetric keys let you verify tokens without ever sharing a secret.
  • Generating keys in-browser keeps private material off the network.

Frequently asked questions

What is the difference between a JWK and a JWKS?

A JWK is one key as JSON. A JWKS is an object with a keys array holding one or more JWKs, served so verifiers can fetch the right public key.

Should I use RS256 or ES256?

Both are secure. ES256 gives much smaller keys and signatures; RS256 has broader library support. Choose based on your verifier.

How do I use the HMAC key?

Share the oct key only with services that both sign and verify. It is symmetric, so there is no public JWKS.

What is the kid for?

It names the key so a verifier can pick the correct one from your JWKS, especially during key rotation.

Is my private key sent anywhere?

No. Generation uses the Web Crypto API in your browser and the private key stays on your device.
