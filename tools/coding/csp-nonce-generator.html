CSP Nonce Generator: Allow Inline Scripts Without Opening the Door

A strict Content Security Policy blocks inline scripts, which is exactly what stops many XSS attacks - until you need one legitimate inline block. A CSP nonce solves that: a fresh random value that whitelists only the scripts you tag with it. This generator creates nonces and the snippets to use them.

How a nonce works

Each response includes a random nonce in the CSP header and on the <script> tags it should allow. The browser runs only scripts whose nonce matches the header. Because the value changes on every response, an attacker cannot predict it, so injected inline scripts are rejected.

Nonce rules to follow

A nonce must be long and unpredictable - at least 128 bits - and regenerated for every response. It must never be reused across requests or cached. The base64 output here is ready for the 'nonce-...' source expression.

How to use CSP Nonce Generator

  1. Choose a nonce size; 16 bytes (128 bits) is the standard baseline.
  2. Generate and copy the nonce into your CSP header.
  3. Add the matching nonce attribute to each allowed script or style tag.
  4. Regenerate the nonce on every response.

Tips for getting accurate results

  • Never reuse a nonce; one leaked value lets an attacker run scripts.
  • 16 bytes is a good default; do not go below 128 bits.
  • Nonces work alongside hashes - use whichever suits each script.

Key takeaways

  • Nonces allow specific inline scripts under a strict CSP.
  • They must be random and per-response.
  • 128 bits of entropy is the sensible minimum.

Frequently asked questions

What is the difference between a nonce and a hash?

A nonce whitelists a tag by attribute per response; a hash whitelists an exact script body. Nonces suit dynamic pages, hashes suit static ones.

How long should a nonce be?

At least 16 random bytes, which is 128 bits and about 24 base64 characters.

Can I reuse the nonce on the same page?

Yes, one nonce per response may tag several scripts, but it must not persist to the next response.

Does a nonce replace CSP entirely?

No. It is one source expression within a policy that still needs the other directives.

Is the nonce sent anywhere?

No. It is generated in your browser.

Nonces let you keep a strict policy and still ship inline code. This CSP nonce generator produces a strong value and the snippets to deploy it. Build the surrounding policy with our CSP generator.
