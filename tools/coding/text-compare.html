Compare Text Without Sending It Anywhere

Diffing two blocks of text is one of the most common tasks in software work: checking what changed in a config, confirming a colleague's edit, or reviewing a copy change in a release note. Problems arise when you paste that text into a web diff service - your proprietary config or unreleased copy now lives on someone else's server.

The Troolify Text Compare tool runs a full line-by-line, word-by-word or character-by-character comparison entirely inside your browser. You see a color-coded side-by-side view, precise change statistics, and can even export the result as a unified diff or a ready-to-apply .patch file - with zero data leaving your tab.

How to Use the Text Compare Tool

  1. Paste the two versions - Original on the left, Modified on the right.
  2. Pick a granularity - Line for whole-line edits, Word to see exactly which words changed, Character to spot single-character typos.
  3. Click Compare - the side-by-side view appears with line numbers and color coding.
  4. Read the stats - lines added, removed and changed are counted for you.
  5. Export if needed - copy the unified diff or download it as a .patch file for your git workflow.

Line, Word and Character Granularity

The granularity you choose controls how precisely the tool shows a change. Line mode aligns the two texts by line and highlights any differing line in yellow, or shows completely added (green) and removed (red) lines. Word mode still aligns by line but splits changed lines into words so a single renamed variable stands out instantly. Character mode goes further and highlights individual characters, which is ideal for catching typos or subtle casing changes that word mode would merge.

Exporting a Unified Diff or .patch

When you need to hand the change to a machine, the tool builds a standard unified diff - the same format git diff produces - with an @@ hunk header and +/- prefixed lines. Download the .patch file, keep the original text alongside it, and apply it with git apply changes.patch or patch -p1 < changes.patch.

Use Cases

Developers diff configuration files before and after refactors, writers compare draft revisions line by line, DevOps engineers review generated manifests for unexpected changes, and QA teams verify that two exported reports differ only where expected. Because everything runs locally, it is safe to compare secrets, contracts and internal documents too.

Frequently Asked Questions

How does comparison granularity work?

Line mode aligns and compares whole lines. Word mode still aligns lines but breaks changed lines into words so you see exactly which words differ. Character mode goes one step further and highlights single characters that changed. Higher granularity makes tiny edits easy to spot.

What is a unified diff and how do I apply a .patch file?

A unified diff is the compact patch format used by git and patch tools, with a header per file followed by context and +/- lines. Download the .patch and apply it with git apply file.patch or patch -p1 < file.patch against the same original text saved as a file.

Are the colors meaningful?

Green marks added text that exists only in the Modified block, red marks removed text that exists only in the Original block, and yellow marks the parts of a changed line that differ between the two.

Is it safe to compare sensitive text?

Yes. The comparison runs entirely in your browser using JavaScript. Your text is never uploaded, stored, or sent to any server.
