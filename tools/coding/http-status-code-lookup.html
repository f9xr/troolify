HTTP Status Code Lookup: What the Server Is Trying to Tell You

Every HTTP response carries a three digit status code, and that code is a compressed summary of what happened. Debugging an API or a website becomes far quicker once you know the code means something specific rather than "an error". This lookup covers the standard codes with a plain-language explanation, the usual cause and the practical fix.

How to Use This Lookup

  1. Type a code, a name or a symptom - "404", "not found", "timeout" all work.
  2. Narrow by class if you only care about client or server errors.
  3. Read the meaning, the cause and the fix, plus any codes that commonly appear alongside it.

The Five Classes

  • 1xx informational: the request was received and the process is continuing.
  • 2xx success: the request was received, understood and accepted. 200 is the ordinary case, 201 means something was created, 204 means success with no content to send back.
  • 3xx redirection: the client needs to go somewhere else. 301 and 308 are permanent, 302 and 307 are temporary, and 304 means the cached copy is still good.
  • 4xx client error: the request was faulty. 400 is malformed, 401 is not authenticated, 403 is authenticated but not allowed, 404 is missing and 429 is rate limited.
  • 5xx server error: the request was valid but the server failed. 500 is a general failure, 502 is a bad gateway, 503 is unavailable and 504 is a gateway timeout.

Status Codes in APIs

REST APIs lean heavily on this vocabulary, and the distinction between 401 and 403 trips people up constantly. 401 means "I do not know who you are" - the credentials are missing or invalid. 403 means "I know exactly who you are and you still may not do this". 422 is increasingly preferred over 400 when the syntax parsed fine but the values were not acceptable, which lets a client tell the two apart and react differently.

Choosing the Right Code

Picking the closest correct code is better than defaulting to 200 with an error message in the body, because clients, monitoring and caches all react to the code. Be honest about failures: a 500 that fires on a routine validation problem is a 500 that stops being noticed when something genuinely breaks. If your API has unusual semantics, document them clearly in the endpoint description.

Frequently Asked Questions

What do the different status code classes mean?

1xx is informational, 2xx means success, 3xx is redirection, 4xx is a client error and 5xx is a server error. That first digit is the fastest way to narrow down where a problem lives before you look at any detail.

What is the difference between a 4xx and a 5xx error?

A 4xx means the request itself was wrong - a bad URL, missing permission or malformed request - so it is usually something the caller can fix. A 5xx means the server failed while handling a valid request, which is your side to investigate.

What is the difference between 301 and 302?

A 301 is a permanent redirect, so browsers and search engines cache it and future requests skip the old URL entirely. A 302 is temporary and is checked again on every request. Using 302 when you mean 301 slows down recovery and hurts search rankings.

Is this list up to date?

It covers the standard status codes defined by the HTTP specifications, from 100 through 511. Non-standard codes do exist and frameworks sometimes invent their own, so check your server logs if you see something that is not listed here.

Conclusion

The first digit of a status code tells you most of what you need: 2 means it worked, 3 means look elsewhere, 4 means the client got something wrong, 5 means your server did. That single habit explains most status codes before you have looked them up. Keep this lookup open while debugging and the second guess stops being a guess.
