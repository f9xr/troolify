DEVELOPERS · TROOLIFY

For Developers

Everything you need to know about how Troolify works behind the scenes - and how to build on it.

There is no server

Troolify is a static site hosted on GitHub Pages. Every tool is a self-contained HTML page whose JavaScript does all the processing in the current tab. There is no backend, no API endpoint, no database, and no build-your-own-key flow. If your data is sensitive - text, files, images, form values - it never leaves your device.

Data-driven tool registry

The site is organized around a single registry: assets/js/tools-data.js exposes window.TOOLS (one entry per tool, with name, description, icon, category, keywords and related-tool links) and window.CATEGORIES (one entry per folder). The homepage, the full catalog, category pages, and the per-tool "related tools" block all render from this registry - adding a tool page in a folder plus one registry entry is enough to make it appear everywhere.

Browser APIs we rely on

  • Web Crypto API - SHA-1/256/384/512 hashing for checksums and integrity checks.
  • Canvas & FileReader - image resizing, conversion, compression, EXIF reads and file manipulation.
  • MediaRecorder & getDisplayMedia - the in-browser screen recorder.
  • URL.createObjectURL / Blob - producing downloadable files without a server.
  • Intl & native date/number APIs - localized formatting on many calculators.

Contribute a tool

Each tool follows a consistent pattern: a panel with inputs, a run handler that writes into #output or #outWrap, a small SEO article with FAQ JSON-LD, and a registry entry. If you build a web utility that fits the site's privacy-first model, we would love to hear about it via the Feedback page.

No tracking, no analytics

Troolify ships without analytics scripts, cookies or fingerprinting. The only third-party requests are the shared font and icon stylesheets (Google Fonts and Font Awesome) needed to render the interface.
